# Dumble Production Rebuild — Design

**Date:** 2026-07-21
**Goal:** Rebuild the Dumble Mumble voice client as a production-ready, Play-Store-publishable app, porting only the features that earn their keep — one human-reviewed PR at a time.

**Architecture:** Single `:app` Gradle module, Kotlin + Jetpack Compose, Hilt DI. Mumble control over TCP (protobuf), voice over UDP with a TCP tunnel fallback, Opus codec, jitter-buffered playout. System call integration via Jetpack `core-telecom`.

**Tech stack (carried from the Android Studio scaffold):** AGP 9.2.1, Gradle 9.6.1, Kotlin 2.2.x, Compose + Kotlin plugins (to be added — the wizard emitted a non-Compose shell), Java 17, compileSdk 36.1 / targetSdk 36 / minSdk 30.

**User decisions (already made):**
- "treat all we've done as a vibe-coded prototype and start from scratch on a more production-ready app to publish in the play store"
- Preserve the prototype on `vibed-prototype`; fresh **orphan** `main`.
- "building one human-reviewed PR at a time, only keeping the features actually being used."
- App name **"Dumble"**, keep `applicationId me.danielstiner.dumble`.
- **minSdk 30** ("Check if we can lower, but I'm fine with 34 if we're actually using relevant features" → measured: 34 not required, chose 30).
- DI **Hilt**; **single `:app` module**.
- Keep-list decided (below); RNNoise, AGC, audio cues **deferred**; scaffold generated by hand in Android Studio.
- Telecom PR sequenced **before** voice; JVM target **Java 17** (both per fable review, 2026-07-21).

## 4. Foundation baseline (PR #1)

- **Identity:** name "Dumble", `applicationId me.danielstiner.dumble`, `versionCode 1` / `versionName 0.1.0`.
- **SDK:** minSdk 30, targetSdk 36, compileSdk 36.1.
- **JVM target:** Java 17 (scaffold defaulted to 11; Google's current baseline).
- **Compose:** add Kotlin Android + Compose compiler plugins, Compose BOM, `activity-compose`,
  `buildFeatures.compose = true`, a Compose theme + `MainActivity`. Remove the wizard's Views deps
  (`appcompat`, Material Components) and Views themes.
- **DI:** Hilt (ksp).
- **Release hardening:** R8/minify **on** for release (scaffold ships it off); real signing config
  reading from a keystore Dan supplies via Gradle properties — **no secrets committed**.
- **CI:** GitHub Actions — assemble **debug + release (R8/minified)** + unit tests on every PR, so R8 keep-rule breakage (protobuf-lite, Hilt, ONNX, JNI) surfaces in CI, not at release.
- **Testing:** JUnit unit tests + the dockerized Murmur integration harness (ported when the
  protocol lands).
- **Module layout:** single `:app` with clean packages (`mumble/{protocol,net,voice}`, `telecom`,
  `ui`, `data`); split to multi-module only if build times demand (YAGNI).

## 5. minSdk investigation (measured, not assumed)

The prototype's minSdk 34 was defensive. Measured from resolved artifacts:

| Dependency / feature | Real floor | Evidence |
|---|---|---|
| `core-telecom:1.0.0` | **API 26** | AAR manifest `minSdkVersion=21`; `CallsManager` class is `@RequiresApi(26)`; bytecode ships both `CallSession` (transactional, 34+) and `CallSessionLegacy` + `JetpackConnectionService` (pre-34 path). |
| onnxruntime-android 1.27.0 (Silero VAD) | API 24 | AAR manifest `minSdkVersion=24`. |
| Compose / current AndroidX | API 21–23 | — |
| FGS `microphone` type | API 30 (clean) | The `microphone` FGS type constant is API 30; `FOREGROUND_SERVICE_MICROPHONE` permission is API 34-only but declared unconditionally (inert on platforms that predate it). |

Nothing requires 34. Chosen floor: **30** (broad reach, clean FGS-microphone semantics).
**Open risk:** the telecom ConnectionService legacy path (`CallSessionLegacy`, what every API 30–33
device actually runs) has only ever run on the API-34 dev device; self-managed `ConnectionService`
phone accounts also carry OEM-dependent friction beyond the transactional path.
**Verification (scheduled right after the Telecom PR, not deferred):** telecom + audio routing on an
API-29/30 emulator, exercising the legacy path — this is the gate that validates the minSdk-30 choice.

## 6. PR roadmap (ordered, reorderable)

1. **Foundation** — Compose + Hilt + R8 + CI (debug + release) + signing stub + deps; empty app launches. (this PR)
2. **Mumble protocol + TCP control** — protobuf schema, codec, TCP transport, crypt, session →
   Synchronized, cert pinning. Headless, tested against the Murmur harness.
3. **Connect UI + roster** — connect screen, server config, live channel/user roster.
4. **Text chat** — control-channel only; validates the protocol round-trip before voice.
5. **Telecom** — system call UI, foreground service, BT/wired/earpiece routing, audio-session
   ownership (`MODE_IN_COMMUNICATION` + audio focus). Ships as a testable silent "call shell" over
   the Mumble connection. Includes the RECORD_AUDIO / POST_NOTIFICATIONS / BLUETOOTH_CONNECT
   runtime-permission flows **and** the API-29/30 emulator verification of the legacy path.
6. **Voice pipeline** — UDP + tunnel, Opus, jitter buffer, mixer, **push-to-talk**, plugged into the
   telecom-owned audio session. Two-way audio, no DSP.
7. **Silero VAD** — voice-activation alongside PTT.
8. **Audio diagnostics page** · 9. **Per-user stats page** — shipped surfaces.
10+. **RNNoise**, **AGC**, **audio cues (redone)**, then Play-readiness (icon/branding, privacy
    policy, **Play Data safety declaration**, permissions onboarding, crash reporting).
